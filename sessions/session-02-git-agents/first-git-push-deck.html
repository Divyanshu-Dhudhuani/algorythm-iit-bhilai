Your first git push, without the password panic.

GitHub rejects account passwords on push. This deck shows the token flow that gets you pushing in five minutes.

Step 1 — Create the token

Four clicks on GitHub.

01

Open settings

GitHub → Settings → Developer settings → Personal access tokens.

02

Fine-grained token

Choose Fine-grained tokens → Generate new token.

03

Name + scope

Name it, set expiry, grant read + write on your repo.

04

Copy once

Generate and copy immediately — it shows only once.

SETTINGS → DEVELOPER SETTINGS → TOKENS02 / 07

Steps 2–4 — Push and persist

Push, paste, and you are done.

1 · Run git push

Run git push as normal. Git prompts for a login.

2 · Paste the token

Username = GitHub username. Password = the token you copied.

3 · Stays saved

Credential Manager / Keychain / libsecret remembers it until expiry.

USERNAME + TOKEN, NOT PASSWORD03 / 07

The gotcha — read after steps 2–4

Password in, “authentication failed” out.

Since GitHub removed password auth for Git operations, pasting your real password at the git push login prompt always fails. Beginners trip here — the fix is using a personal access token as the password.

$ git push
Username: your-github-username
Password: paste-token-here (not your password)
SOURCE: FIRST-GIT-PUSH-SETUP.MD04 / 07

If nothing prompts you

One config line, then push again.

$ git config --global credential.helper store
$ git push # now enter username + token

Want zero prompts next time? Set up an SSH key with ssh-keygen -t ed25519, add it under Settings → SSH keys, and clone via git@github.com:…
